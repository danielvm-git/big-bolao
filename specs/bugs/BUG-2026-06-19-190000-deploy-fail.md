# BUG-2026-06-19-190000: Deploy falha — RootPath não propagado ao DetectAppType

## Problem

O deploy do site no BigBase Sites falhou com o erro:

```
Detected app type: python
Running: pip install -r requirements.txt
Command failed: exec: "pip": executable file not found in $PATH
Deploy failed
```

- **Comportamento observado**: A plataforma detectou o app como Python porque encontrou `requirements.txt` na raiz do repositório clonado e tentou executar `pip install`. O `pip` não está disponível no ambiente de build do BigBase.
- **Comportamento esperado**: O deploy deveria respeitar o `root_path` configurado (`web/`, conforme story e01-s11), detectar o `package.json` nesse subdiretório, e construir como app Node.js com `npm install && npm run build`, servindo o output estático de `web/dist/`.
- **Como reproduzir**: Criar um site no BigBase com `root_path = "web/"`. O deploy ignora o campo e detecta a partir da raiz do clone.

## Root Cause Analysis

**Causa raiz**: O campo `root_path` existe na tabela `sites` e é exposto via API, mas **nunca é propagado ao fluxo de deploy**. O componente `deploy` clona o repositório inteiro para um diretório temporário e chama `DetectAppType(buildDir)` — onde `buildDir` é a raiz do clone, não o subdiretório configurado como `root_path`.

A função `DetectAppType` inspeciona arquivos na raiz do clone:

1. Se encontrar `package.json` → classifica como Node
2. Se encontrar `go.mod` → classifica como Go  
3. Se encontrar `requirements.txt` → classifica como Python
4. Caso contrário → classifica como Static

Como o repositório tem `requirements.txt` na raiz (bot Telegram) e `package.json` apenas em `web/`, a detecção sempre classifica como Python — independentemente do valor de `root_path`.

**Evidência do código** (componente `deploy`): `DetectAppType` recebe apenas `buildDir` (string do diretório clonado), sem parâmetro de subdiretório. O campo `RootPath` do modelo `Site` (componente `sites`) nunca é passado para o componente `deploy`.

**Fator contribuinte**: O build de apps Python usa `pip` diretamente (`exec.CommandContext(ctx, "pip", "install", ...)`) em vez de `python3 -m pip`, que seria mais portátil entre ambientes.

Isto explica por que o usuário reportou "still the same" após alterar o `root_path` — o campo não tem efeito.

**Risk level**: Medium — requer alteração no código-fonte do BigBase (componente `deploy`). O workaround de projeto (mover `requirements.txt` ou adicionar `package.json` na raiz) é Low risk.

## TDD Fix Plan

O plano possui duas camadas: (A) workaround imediato no projeto para desbloquear o deploy, e (B) fix definitivo no BigBase.

### Camada A — Workaround: package.json na raiz do repo

Como `DetectAppType` verifica `package.json` ANTES de `requirements.txt`, basta adicionar um `package.json` na raiz que delegue o build para `web/`.

1. **RED**: Deploy atual falha — `DetectAppType` retorna Python, `pip` não encontrado.
   **GREEN**: Criar `package.json` na raiz do repositório com script de build que chama `cd web && npm install && npm run build` e copia/usa `web/dist/` como saída.
   **verify**: 
   ```
   cd /tmp && git clone <repo> test-clone && cd test-clone
   npm install && npm run build
   test -d dist/ && echo "OK: dist/ exists"
   ```

2. **RED**: Build output em `web/dist/` não é encontrado pelo BigBase (procura `dist/` na raiz do clone).
   **GREEN**: Configurar o build script para copiar `web/dist/` → `dist/`, ou configurar o Vite com `outDir: '../dist'`.
   **verify**: Após `npm run build` na raiz, `ls dist/index.html` existe.

3. **RED**: Build Node falha se `npm` não estiver no PATH.
   **GREEN**: Verificar que `node` e `npm` estão disponíveis no ambiente BigBase (já são usados para admin UI do BigBase — confirmado pelo build do admin dashboard).
   **verify**: Inspecionar log de build no BigBase — deve mostrar `npm install` e `npm run build` bem-sucedidos.

### Camada B — Fix definitivo: propagar RootPath no BigBase deploy

4. **RED**: `DetectAppType` ignora `root_path` — campo armazenado mas não utilizado.
   **GREEN**: Modificar a assinatura de `DetectAppType` para aceitar `rootPath string` e inspecionar arquivos em `filepath.Join(buildDir, rootPath)`. Propagar `root_path` da tabela `sites` até `runDeployment`.
   **verify**: Teste unitário em `deploy_test.go`:
   ```
   go test ./components/deploy/ -run TestDetectAppType -v
   ```

5. **RED**: `buildApp` para Python usa `pip` diretamente (binário pode não existir).
   **GREEN**: Alterar para `python3 -m pip install -r requirements.txt`.
   **verify**: 
   ```
   go test ./components/deploy/ -run TestBuildApp -v
   ```

**REFACTOR**: Extrair `resolveBuildDir(baseDir, rootPath string) string` como helper para evitar repetição da lógica `filepath.Join` nos métodos `buildApp`, `DetectAppType`, `serveStatic`, e `startApp`.
